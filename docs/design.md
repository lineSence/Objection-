# Objection! — проектный документ

**Цель:** открытый оркестратор «совета моделей». Любые LLM через LiteLLM; протокол подбирается под тип задачи; факты проверяются инструментами; качество измеряется против одиночной модели; состав совета подбирается по данным из пула, который задаёт пользователь. Работает и для человека, и как шаг в цикле агентной разработки (OpenCode, Cline).

## 0. Ключевые решения

Полный журнал — [decisions.md](decisions.md).

## 1. Грабли, которые мы обходим

Подробно — [research.md](research.md).

| Грабли | Наш ответ |
| --- | --- |
| Дебаты ≈ голосование, часто хуже CoT / self-consistency | Спор — только эскалация при несогласии, ≤ 1–2 раундов; baseline всегда измеряется |
| Угодничество, конформизм, отказ от правильных ответов | Независимый первый раунд, анонимизация, анти-конформистские промпты, смена позиции только с указанием довода; оценка по всей траектории, а не по последнему раунду |
| Коррелированные ошибки (9 судей ≈ 2 независимых голоса) | Совет 3–5 моделей, подбор по измеренной независимости ошибок (n_eff) |
| Слабые модели тянут группу вниз | Model Registry исключает модели без вклада; допускаются несколько сэмплов одной сильной модели |
| Предвзятый судья (позиция, длина, «своя» модель) | Анонимизация, перестановка порядка, судья из другого семейства; где можно — итог считает код |
| Галлюцинации и общие неверные допущения | Verifier: поиск, python, тесты |
| Неоднозначный вопрос | Фаза Clarify; в агентном режиме — явные допущения |
| Стоимость растёт как N² | Ранняя остановка, разрежённая топология, сжатый контекст (Claim Ledger), жёсткий бюджет |
| Ложный консенсус / ложный победитель | Несогласие — первоклассное поле результата; мнение меньшинства сохраняется |
| Prompt injection, рекурсия, заброшенные «хаки выходного дня» | Данные ≠ инструкции, песочница, лимит глубины; тесты и mock-провайдер с первого дня |
| Жёсткая привязка к конкретным моделям/CLI | Только LiteLLM + пользовательский пул |

## 2. Протоколы (пресеты)

**Task Router** определяет тип задачи (дешёвая модель-классификатор из пула; флаг `--mode` всегда приоритетнее).

| Пресет | Для чего | Схема | Как решается итог |
| --- | --- | --- | --- |
| `verify` | Проверяемый ответ: математика, факты, логика | N независимых ответов → нормализация → согласны? стоп : 1 раунд анти-конформистской критики → Verifier | Код: взвешенное голосование; результаты проверки приоритетнее |
| `code` | Генерация / исправление кода | Несколько решений → тесты в песочнице → при провале критика с логами тестов | Тесты; при равенстве — ревью панелью |
| `review` | Ревью диффа, документа, плана | Независимые ревью в чистом контексте → дедупликация находок → перекрёстная проверка каждой находки | Ранжированный список находок: severity + число подтверждений |
| `deliberate` | Решения, архитектура, стратегия, риски | Независимые ответы → структурный анализ (консенсус / противоречия / уникальное / слепые зоны) → опц. 1 анонимный раунд критики → фактчек ключевых утверждений | Синтез с вариантами и компромиссами; разногласия сохраняются |
| `quick` | Простые вопросы | 2 разнородные модели; согласны — готово, иначе эскалация | Совпадение ответов |

Пресеты — YAML-конфиги над общими фазами: `clarify`, `independent`, `analyze`, `critique`, `verify`, `aggregate`, `synthesize`. Можно собирать свои.

## 3. Архитектура

```
Interfaces:  Python API │ CLI (JSON/Markdown, exit codes) │ MCP-сервер │ (позже) HTTP API + Web UI
                │
Task Router ──► Protocol Engine (пресеты, фазы, топология, остановка)
                │
   ┌────────────┼───────────────┬────────────────┐
   │ Claim      │ Verifier       │ Aggregator      │
   │ Ledger     │ (web, python,  │ (weighted vote, │
   │            │  tests, repo)  │  Borda, judges, │
   │            │                │  synthesis)     │
   └────────────┴───────────────┴────────────────┘
                │
Model Pool (пользовательский конфиг) + Model Registry (статистика, корреляция ошибок, цена)
Budget Manager │ Run Store (SQLite) │ Cache
Eval Harness (бенчмарки + свои задачи из истории)
                │
LiteLLM (облачные API, Ollama / vLLM / LM Studio; фоллбэки, ретраи, учёт $)
```

## 4. Подсистемы

### 4.1 Model Pool и Model Registry

- **Пул** задаёт пользователь (конфиг + команды `objection models add/remove/list/check`). Он может меняться между любыми запусками.
- **Health check** перед запуском: недоступные модели исключаются с предупреждением, совет собирается из оставшихся.
- **Registry** хранит статистику по `model id`: точность по типам задач, цена, задержка, семейство, попарная корреляция ошибок.
- Новая модель стартует с нейтральным приоритетом (опц. мини-eval при добавлении); исчезнувшая просто не участвует, история сохраняется.
- **Автовыбор** состава (3–5 моделей) — только внутри текущего пула: максимизировать точность и n_eff = k / (1 + (k−1)·φ̄) при бюджете; модели без вклада (leave-one-out) не берутся. Ручное закрепление состава (`pinned`) всегда доступно.
- **Локальные модели:** отдельные таймауты и лимит параллелизма на endpoint, стоимость = 0.

### 4.2 Verifier (фактчек)

- Извлечение проверяемых утверждений в Claim Ledger: факт, число, код, ссылка.
- Инструменты: веб-поиск с цитатой, python-песочница, запуск тестов, чтение репозитория.
- Статусы: `confirmed` / `refuted` / `unverified` + доказательство. Опровергнутое утверждение снижает вес ответа автора.
- Правило: непроверенный аргумент не может перевесить проверенный факт.
- Результаты инструментов — данные, не инструкции.

### 4.3 Eval Harness

- Всегда три baseline при **равном бюджете**: лучшая одиночная модель пула, self-consistency лучшей модели, простое голосование.
- Наборы: GSM8K/MATH, GPQA, HumanEval / SWE-bench-lite + свой набор из размеченных запусков Run Store.
- Метрики: точность, $ и секунды на задачу, переходы правильный↔неправильный, калибровка уверенности, сохранность правильного меньшинства.
- Если пресет не бьёт baseline на данном пуле — по умолчанию он не включается.
- Так как пул меняется, eval можно перезапускать на текущем пуле одной командой (`objection eval`).

### 4.4 Открытость

- MIT, расширяемые фазы / пресеты / инструменты.
- Полный лог каждого запуска: промпты, ответы, стоимость, почему принят итог.
- Публичные результаты eval в репозитории.
