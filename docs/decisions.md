# Журнал решений

Формат: дата — решение — причина — следствия.

## D-001 · 2026-09-29 · Несколько протоколов вместо одного «дебата»
- **Решение:** задачи разноплановые → Task Router + пресеты `verify`, `code`, `review`, `deliberate`, `quick`.
- **Причина:** исследования показывают, что наивный дебат ≈ голосование и часто хуже self-consistency; разные задачи требуют разных механизмов принятия итога.
- **Следствие:** протокол — это YAML-конфиг над общими фазами.

## D-002 · 2026-09-29 · Основной пользователь — автор и агентный цикл разработки
- **Решение:** сначала библиотека + CLI + MCP-сервер с машиночитаемым JSON; веб и многопользовательский режим — позже.
- **Следствие:** неинтерактивный режим (допущения вместо уточняющих вопросов), verdict + exit code, лимиты бюджета, кэш.

## D-003 · 2026-09-29 · Провайдеры через LiteLLM
- **Решение:** единый слой LiteLLM для всех моделей.
- **Следствие:** никаких адаптеров под конкретного провайдера; фоллбэки, ретраи, учёт стоимости — средствами LiteLLM.

## D-004 · 2026-09-29 · Отличие от аналогов — по четырём направлениям
- **Решение:** открытость, фактчек инструментами, измеримое качество, подбор моделей по данным.
- **Следствие:** подсистемы Verifier, Eval Harness, Model Registry — часть ядра, а не «когда-нибудь».

## D-005 · 2026-09-30 · Первые агенты-клиенты — OpenCode и Cline
- **Решение:** MCP-сервер проверяется в первую очередь с OpenCode и Cline.
- **Следствие:** stdio-транспорт MCP как основной; инструкции по подключению в `integrations.md`; e2e-проверка на обоих клиентах в M1.

## D-006 · 2026-09-30 · Пул моделей задаёт пользователь, и он часто меняется
- **Решение:** никаких захардкоженных моделей. Пул — в пользовательском конфиге, может меняться между запусками.
- **Следствие:**
  - Model Registry — это статистика по тем моделям, что реально есть в пуле, а не каталог.
  - При каждом запуске: проверка доступности (health check), неработающие модели исключаются с предупреждением.
  - Статистика хранится по `model id`; новые модели стартуют с нейтральным приоритетом и накапливают историю; исчезнувшие — просто не участвуют.
  - Автовыбор состава работает только внутри текущего пула; пользователь может закрепить состав вручную.
  - Команды `objection models list/check/add/remove`.

## D-007 · 2026-09-30 · Локальные модели поддерживаются, но не основной путь
- **Решение:** Ollama / vLLM / LM Studio (OpenAI-совместимые) — поддерживаются через LiteLLM, тестируются, но оптимизация идёт под облачные API.
- **Следствие:** учитывать медленные локальные модели (отдельные таймауты, ограничение параллелизма на endpoint), нулевую стоимость в бюджете.

## D-008 · 2026-09-30 · Название и лицензия
- **Решение:** проект называется **Objection!**, лицензия **MIT**. Репозиторий: `lineSence/Objection-` (GitHub заменил `!` на `-`).
- **Следствие:** имя пакета/CLI — `objection`.

## D-009 · 2026-09-30 · Web UI — с первого этапа
- **Решение:** Web UI входит в M0, а не откладывается до M5. Основа — пять макетов из `docs/webui/mockups/`: Обзор, Вопрос (чат + инспектор), Ход запуска, виды «Спор» и «Отчёт».
- **Следствие:**
  - Ядро с самого начала пишет события этапов в Run Store и отдаёт их потоком (SSE) — UI и CLI используют одни данные.
  - Команда `objection ui`, локальный сервер на `127.0.0.1`; многопользовательский режим — по-прежнему M5.
  - Виды, зависящие от других подсистем, появляются вместе с ними: подсветка фактов — с Verifier (M3), метрики точности — с Eval Harness (M4).

## D-010 · 2026-09-30 · Светлая и тёмная темы
- **Решение:** три режима — Авто (системная), Светлая, Тёмная. Все цвета — CSS-переменные; тёмная тема переопределяет только их.
- **Следствие:** никаких жёстко заданных цветов в компонентах; одинаковая семантика цветов в обеих темах; проверка контраста (WCAG AA) для обеих.

## D-011 · 2026-09-30 · Стек Web UI: FastAPI + React/TypeScript
- **Решение:** бэкенд — FastAPI внутри Python-пакета `objection`; фронтенд — React + TypeScript, сборка Vite.
- **Следствие:**
  - Исходники фронтенда в `web/`, сборка пишется в `src/objection/web_dist/` и попадает в wheel; собранная версия хранится в репозитории — установка из git не требует Node.
  - API: `GET/POST /api/runs`, `GET /api/runs/{id}`, `GET /api/runs/{id}/events`, `GET /api/runs/{id}/stream` (SSE), `GET /api/models`, `POST /api/models/check`.
  - Роутинг на hash (`#/runs/<id>`), без сторонних UI-библиотек; тема — CSS-переменные (D-010).

## D-012 · 2026-09-30 · Устройство M1: MCP, review, критика
- **Решение:**
  - MCP-сервер на официальном Python SDK 2.x (`mcp>=2.2,<3`, `MCPServer`), транспорт stdio. Источник запуска берётся из `clientInfo` клиента (OpenCode / Cline).
  - `review`: вердикт `pass/fail/uncertain` вычисляет код по голосам перекрёстной проверки и порогу `fail_on`, а не модель-председатель. Подтверждение — ≥ 2 голосов и перевес над опровержениями. Председатель только объединяет дубликаты и не может выбросить находку.
  - Раунд критики в `deliberate` — разреженное кольцо: каждая модель видит 2 чужих анонимных ответа (а не все), промпт требует держать позицию без новых аргументов (против конформизма). Смена позиции фиксируется явно (`changed`, `reason`).
  - Кэш: ключ — хэш (режим, вопрос, контекст, материал, состав, порог, версия протокола); хранится в том же SQLite.
- **Следствие:** агент может детерминированно ветвиться по `verdict`/exit code; стоимость критики растёт линейно по числу моделей; при смене промптов поднимается `PROTOCOL_VERSION`, чтобы не отдавать устаревший кэш.

## D-013 · 2026-09-30 · Настройки моделей и ключей в Web UI
- **Решение:**
  - Пул моделей, ключи API и совет по умолчанию редактируются в Web UI («Настройки»). Изменения сразу применяются к работающему серверу и пишутся в `config.yaml` (прочие секции сохраняются, предыдущая версия — в `config.yaml.bak`).
  - Ключи хранятся отдельно от конфига: `~/.objection/secrets.env`, права 0600; API отдаёт только маску (`••••1234`). Ключи из файла перекрывают переменные окружения. Для своих серверов — ключ на модель (`api_key_env`).
  - Модели описываются строкой LiteLLM `provider/model`; `params` передаются в `litellm.completion` как есть (`drop_params` включён). Пресеты провайдеров: облачные API, Ollama, LM Studio, LiteLLM Proxy, OpenAI-совместимый URL; подсказки — из встроенного каталога цен LiteLLM (без сети) и из `/models` / `/api/tags` локального сервера.
  - Защита локального сервера: запросы с чужим `Host` (DNS rebinding) и изменяющие запросы с чужим `Origin` отклоняются (403).
- **Следствие:** живую проверку моделей можно сделать целиком в браузере; при запуске UI на не-локальном адресе потребуется явный список разрешённых хостов (M5).

## D-014 · 2026-09-30 · M2: авто-режим, голосование, код по тестам, бюджет
- **Решение:**
  - Режим по умолчанию — `auto`. Сначала бесплатные правила (есть материал → `review`, есть команда тестов → `code`), затем одна короткая классификация самой дешёвой моделью совета (`quick` / `verify` / `deliberate`), при сбое — эвристика по ключевым словам. Явно указанный режим всегда главнее. Причина выбора сохраняется (`route_reason`, событие `route`).
  - `verify` и `quick` сравнивают **нормализованные короткие ответы** (регистр, пунктуация, да/нет → true/false, числа), вес голоса = `weight` модели × (0.5 + 0.5 · уверенность). Итог и `uncertain` (ничья, `unknown`, доля < 50 %) считает код.
  - Ранняя остановка: при единогласии критика не запускается; оценка экономии — стоимость пропущенного раунда (`saved_usd_est`). `quick` при расхождении эскалирует в `verify`, переиспользуя два уже полученных ответа.
  - Критика в `verify` — все видят все чужие ответы (анонимно, в случайном порядке для каждого), менять ответ можно только с названным доводом.
  - `code`: победителя выбирают тесты, а не модель; при нескольких прошедших — решение первого раунда, затем самое короткое. Один раунд исправлений, только если не прошёл никто. Без команды тестов выбирает председатель. Исходная папка проекта не меняется — каждый кандидат тестируется во временной копии. Изоляции (песочницы) пока нет — M3.
  - Budget Manager: перед каждым вызовом оценка стоимости (≈ длина/3.5 токенов входа + 800 выхода; цены — `price_in`/`price_out` модели или прайс LiteLLM; локальные и неизвестные — 0), с резервом под параллельные вызовы. Вызов, который вывел бы за бюджет, пропускается (`model_error` с `budget: true`); протоколы отдают частичный результат `uncertain`, а не падают.
- **Следствие:** простые вопросы стоят 2 вызова вместо 2N+1; `PROTOCOL_VERSION` = `m2.0` (старый кэш не используется); оценка бюджета приблизительна — фактическая стоимость может превысить лимит не больше чем на ошибку оценки одного вызова.
