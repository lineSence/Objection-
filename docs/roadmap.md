# Roadmap

- [x] **M0 — каркас**
  - [x] Python-пакет `objection`, конфиг пула моделей, LiteLLM, mock-провайдер
  - [x] Параллельные независимые ответы, пресет `deliberate` (анализ + синтез)
  - [x] JSON/Markdown-вывод, Run Store (SQLite), CLI `ask` / `runs` / `ui`
  - [x] `objection models list/check` — health check пула
  - [x] Web UI (`objection ui`): «Вопрос» и «Ход запуска», события через SSE, темы Авто/Светлая/Тёмная
  - [x] Кэш (перенесён в M1)
  - [x] Полноценный Budget Manager (сделан в M2)
- [x] **M1 — агентный цикл**
  - [x] MCP-сервер (stdio, MCP SDK 2.x), инструменты `council_ask`, `council_review`, `council_models`, прогресс и ссылка на запуск в UI
  - [x] Пресет `review`: независимые ревью → объединение дубликатов → перекрёстная проверка → вердикт кодом
  - [x] `objection review` (файл / stdin / `--diff` / `--staged`), `--format json`, exit code 0/1/2/3
  - [x] Раунд перекрёстной критики в `deliberate` (разреженное кольцо: каждый видит 2 анонимных ответа)
  - [x] Кэш результатов (SQLite), `--no-cache` / `no_cache`
  - [x] Инструкции подключения OpenCode и Cline; живой прогон в OpenCode 1.18.33 и Cline CLI 3.0.66 (скриптовая модель, `tests/e2e/`)
  - [x] Web UI: «Обзор» (запуски по источникам, расходы, вердикты, пул с проверкой), вид «Спор» (колонки позиций / матрица голосов), режим «Ревью» в композере
- [x] **M1.5 — настройки моделей в Web UI**
  - [x] Пул моделей LiteLLM, ключи API, совет по умолчанию; проверка подключения; поиск моделей на локальных серверах и LiteLLM Proxy
- [x] **M2 — verify / code / quick**
  - [x] Task Router: режим `auto` (по умолчанию) — правила (материал → `review`, тесты → `code`) + классификация самой дешёвой моделью, эвристика как запасной вариант
  - [x] `verify`: короткие ответы → взвешенное голосование → единогласно? ранняя остановка : анти-конформная критика → переголосование
  - [x] `quick`: две модели разных провайдеров, при расхождении — эскалация на весь совет с переиспользованием ответов
  - [x] `code`: кандидаты от всех моделей → тесты на каждом во временной копии проекта → раунд исправлений по логам → победитель по тестам
  - [x] Budget Manager: оценка стоимости до вызова, резерв для параллельных вызовов, пропуск вызова вместо превышения, частичный результат `uncertain`; цены на модель (`price_in`/`price_out`)
  - [x] Вес голоса модели (`weight`), анонимизация и перестановка (в т. ч. в перекрёстной проверке ревью)
  - [x] `council_verify`, `council_solve`, `council_ask(mode=…)`; CLI `verify`, `solve`, `ask --mode`
  - [x] Web UI: режимы в композере, голоса и ранняя остановка, эскалация, кандидаты и тесты, матрица «модель × раунд», экономия на «Обзоре»
  - [x] Песочница для `code` — сделана в M3
- [x] **M3 — Verifier**
  - [x] Claim Ledger: извлечение утверждений с авторами, статусы supported / refuted / unverified, источники, судьи
  - [x] Веб-поиск через SearXNG (JSON API), судьи из моделей-неавторов; python-проверки в песочнице
  - [x] `deliberate`: исправление ответа при опровержении; `verify`: доказательство главнее голосов (`fact_override`)
  - [x] Песочница без Docker (временная копия, очищенное окружение, rlimits, таймаут, без сети на Linux) для тестов `code` и python-проверок; `objection sandbox`
  - [x] Защита от prompt injection в результатах инструментов (`<untrusted>`, пометка подозрительного)
  - [x] `check_facts` в `council_ask` / `council_verify`, CLI `--check/--no-check`
  - [x] Web UI: вид «Отчёт» с подсветкой, блок «Проверка фактов», шаги в «Ходе», настройки фактчека (с проверкой SearXNG) и песочницы, KPI «Фактчек»; удаление запусков
  - [x] Фактчек для `review`; чтение файлов репозитория как источник доказательств (метод `repo`)
- [x] **M3.1 — стабилизация**
  - [x] Кэш по содержимому `workdir` и настройкам Verifier / песочницы (`m3.1`)
  - [x] CI (GitHub Actions): pytest на Linux / macOS / Windows, проверка, что собранный Web UI совпадает с исходниками
  - [x] Health check перед запуском, `excluded_models`, добор совета; ретраи и `fallbacks`
  - [x] Семейства моделей (`family`), председатель и судьи из другого семейства
  - [x] Таблица исходов по моделям (`model_outcomes`), `objection runs reindex`
  - [x] Разметка итогов: `objection runs label`, 👍/👎 в Web UI, `POST /api/runs/{id}/label`
  - [x] `objection models add/remove`
- [ ] **M4 — измеримость**
  - [x] Eval Harness: `objection eval run/list/show`, три baseline при равном бюджете, метрики (точность, $, флипы, калибровка, меньшинство, φ, n_eff), наборы `math-mini` / `code-mini` / `mine` / свой `.jsonl`; `auto` избегает проигравших пресетов
  - [ ] Model Registry: статистика по моделям пула, корреляция ошибок, n_eff, автовыбор состава (`council.selection: auto`), `objection models stats`
  - [ ] Web UI: страница «Оценки (eval)», метрики на «Обзоре»
- [ ] **M5 — другие пользователи**
  - HTTP API, многопользовательский Web UI (авторизация), BYO-ключи
  - Публичные результаты eval
