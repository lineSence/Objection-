# Интеграция с агентами разработки

Objection! подключается к агентам как **MCP-сервер** (транспорт stdio по умолчанию). Первые целевые клиенты — **OpenCode** и **Cline**; оба поддерживают подключение MCP-серверов.

> Точные ключи конфигурации клиентов уточняются на этапе M1 по актуальной документации OpenCode и Cline и фиксируются здесь с проверенными примерами.

## Инструменты MCP-сервера (план)

| Инструмент | Вход | Выход | Когда агенту вызывать |
| --- | --- | --- | --- |
| `council_ask` | вопрос, контекст, `mode` (опц.) | ответ, уверенность, разногласия | архитектурное решение, выбор подхода |
| `council_review` | дифф / файл / план, критерии | `verdict`, находки с severity | перед коммитом / PR, перед реализацией плана |
| `council_verify` | утверждение, контекст | статус (confirmed / refuted / unverified), доказательства | сомнительный факт, API, число |
| `council_solve` | задача + команда запуска тестов | лучшее решение, результаты тестов | агент застрял, тесты падают повторно |
| `council_models` | — | текущий пул и его доступность | диагностика |

## Правила для агентного режима

- **Чистый контекст ревьюеров:** модели совета видят только задачу, дифф и нужные файлы — не историю диалога агента-автора.
- **Неинтерактивность:** вместо уточняющих вопросов — поле `assumptions`.
- **Жёсткие лимиты:** `budget_usd`, `timeout_s` на вызов; при превышении — частичный результат с `verdict: "uncertain"`.
- **Без рекурсии:** совет не может вызвать совет (метка глубины в запросе).
- **Кэш:** хэш (вход + состав + пресет) → повторный вызов в цикле бесплатен.
- **Ветвление:** агент опирается на `verdict` (`pass` / `fail` / `uncertain`) и `findings[].severity`.

## Рекомендуемые точки вызова в цикле

1. План готов → `council_review` плана.
2. Код написан, тесты зелёные → `council_review` диффа.
3. Тесты красные 2+ раза подряд → `council_solve` или `council_ask` «второе мнение».
4. Агент опирается на неочевидный факт (версия API, поведение библиотеки) → `council_verify`.

## CLI для CI

```bash
objection review --diff HEAD~1 --format json --fail-on high
# exit 0 — pass, 1 — fail, 2 — uncertain, 3 — ошибка конфигурации/бюджета
```
