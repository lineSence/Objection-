# Web UI

Web UI есть с первого этапа (D-009). Его задача — показать не только ответ, но и **как совет к нему пришёл**: позиции, возражения, проверку фактов и стоимость.

Макеты: [`webui/mockups/`](webui/mockups/). Откройте HTML в браузере; тёмная тема — `?theme=dark` в адресе.

| 1 | **Обзор** | [4-dashboard](webui/mockups/4-dashboard.html) | Главная: запуски из всех источников (Web, OpenCode, Cline), пул моделей с health check, расходы, метрики eval |

Экраны 2–5 — это **виды одного запуска** (переключатель вкладок: Чат · Ход · Спор · Отчёт), а не разные сущности.

## Темы

- Три режима: **Авто** (по `prefers-color-scheme`), **Светлая**, **Тёмная**. Выбор хранится в `localStorage`, переключатель — внизу боковой панели.
- Все цвета — CSS-переменные (`--bg`, `--card`, `--t`, `--t2`, `--b`, `--s`, `--s2`, акценты `--blue/--g/--o/--r` и их подложки `*S`, цвета текста тегов `*T`). Тёмная тема переопределяет только переменные в `[data-theme=dark]`; в компонентах не должно быть жёстко заданных цветов.
- Семантика цветов одинакова в обеих темах: зелёный — подтверждено / согласие, красный — Objection! / опровергнуто, оранжевый — спорно / смена позиции, синий — действие / выбор.
- Контраст текста — не ниже WCAG AA в обеих темах.

## Данные и обновления

- UI читает то же, что пишет ядро: Run Store (SQLite), события запуска, итоговый JSON-вердикт. Своей логики дебатов в UI нет.
- Живые обновления идущего запуска — через SSE (поток событий этапов).
- Запуски из MCP (OpenCode, Cline) появляются в UI автоматически, с меткой источника.

## Запуск

- `objection ui` — локальный сервер, по умолчанию `127.0.0.1`, без авторизации (однопользовательский режим).
- Многопользовательский режим (авторизация, BYO-ключи) — M5.

## Стек и код (D-011)

- Бэкенд: FastAPI в `src/objection/server.py`. Фронтенд: React + TypeScript + Vite в `web/`.
- Сборка `npm run build` пишет в `src/objection/web_dist/`, оттуда статику раздаёт FastAPI.
- Разработка: `objection ui --no-open` и `npm run dev` в `web/` (Vite проксирует `/api` на `:6967`).
