# Verifier: проверка фактов (M3)

После ответа совета Verifier извлекает из него проверяемые утверждения (Claim Ledger), проверяет каждое **веб-поиском через SearXNG** или **коротким python-скриптом в песочнице** и, если что-то опровергнуто, просит председателя исправить ответ.

## Когда работает

| Режим | Что проверяется |
| --- | --- |
| `deliberate` | Итоговый ответ: председатель извлекает до `max_claims` утверждений (с авторами — какие модели их высказали), после проверки — исправление ответа (`revise`) |
| `verify` | По одному утверждению на каждую группу голосов. **Доказательство главнее голосов:** подтверждённый кандидат побеждает, опровергнутые выбывают; если опровергнуты все — итог `uncertain` (`fact_override`) |
| `quick` | Только если явно попросить (`check_facts: true` / `--check`) или режим включён в `verifier.modes` |
| `review` | Только если явно попросить (`check_facts: true` / `--check`) или `review` в `verifier.modes`. По одному утверждению на находку («находка реальна ⇔ утверждение верно»), в первую очередь серьёзные. `supported` → находка подтверждена, `refuted` → отклонена — даже вопреки голосам |
| `code` | Не проверяется (истину устанавливают тесты) |

По умолчанию — `verifier.modes: [deliberate, verify]`. Явный флаг запроса главнее: `council_ask(check_facts=true|false)`, `objection ask --check/--no-check`, переключатель «фактчек» в композере Web UI.

## Как решается статус

- **python** (арифметика, даты, поведение стандартной библиотеки): модель пишет скрипт, который печатает `{"holds": true|false, "value": …}`. Статус задаёт вывод кода; ошибка / таймаут → переходим к поиску.
- **search**: запрос в SearXNG → топ-`search_results` результатов → `judges` судей (по умолчанию 2) оценивают утверждение **только по этим источникам**. Судьи выбираются в первую очередь из моделей, которые утверждение *не* высказывали. Итог — `supported`/`refuted`, только если все решительные голоса совпали и решительных не меньше половины; иначе `unverified`.
- **repo** (утверждения о коде проекта: функция есть / не обрабатывает ошибку, значение по умолчанию, содержимое конфига): поиск по файлам `workdir` запуска — идентификаторы и точные строки из `query`, приоритет файлу из `path`. Только текстовые файлы ≤ 512 КБ, без `.git` / `node_modules` / venv и симлинков; до `repo_results` фрагментов по ±3 строки уходят судьям в `<untrusted>`. Без `workdir` утверждение проверяется поиском. `workdir` задаётся в `council_review` / `council_ask`, `objection review` (по умолчанию — текущая папка) и `objection ask --workdir`.
- Без поиска и без python (SearXNG недоступен) утверждение остаётся `unverified` — Verifier не гадает.

Результат: `verdict.claims[]` (`text`, `quote`, `method`, `status`, `evidence`, `sources[]`, `judges`, `authors`, `flagged`), `verdict.revised`, `verdict.original_answer`, `verdict.fact_override`. Всё это в JSON-выводе CLI, MCP-инструментах и Web UI (вкладка «Отчёт», блок «Проверка фактов» в чате, шаги «Проверка» в «Ходе запуска»).

## Защита от prompt injection

Всё, что пришло от инструментов (сниппеты поиска, вывод тестов и скриптов), считается **данными, а не инструкциями**:

- текст очищается от управляющих символов и тегов, обрезается и оборачивается в `<untrusted source="…">…</untrusted>`; системные промпты судей и кодеров прямо запрещают исполнять инструкции внутри этих блоков;
- эвристика помечает подозрительные фрагменты («ignore previous instructions», «system prompt», …) — `flagged: true`, в UI — предупреждение;
- судьи не видят ответы совета, только утверждение и источники; вердикт (голоса → статус) считает код.

Это снижает риск, но не исключает его полностью.

## Настройка SearXNG

Objection! обращается к `GET {searxng_url}/search?q=…&format=json`. В SearXNG JSON-формат по умолчанию **выключен** — без него будет ошибка 403. В `settings.yml`:

```yaml
search:
  formats:
    - html
    - json
```

Перезапустите SearXNG и проверьте: `curl 'http://localhost:8888/search?q=test&format=json'`. В Web UI: **Настройки → Фактчек → Проверить**.

```yaml
verifier:
  enabled: true
  modes: [deliberate, verify]
  web_search: true
  searxng_url: http://localhost:8888
  search_results: 5
  python: true
  max_claims: 5
  judges: 2
  revise: true
  repo: true          # файлы workdir как доказательства
  repo_results: 6
```

Стоимость: извлечение (1 вызов) + до `max_claims × judges` коротких вызовов + исправление (1 вызов, только если есть опровержения). Все вызовы идут через Budget Manager.
